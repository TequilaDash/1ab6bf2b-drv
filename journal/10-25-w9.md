## 第五十六波：panic 完整解码 + 二次复现——引擎 slot 分配器 NULL 解引用，CVE 现场定位
- **用户抓到 panic ips**（panic-full-2026-10-25-121952.ips）。panicString：`Kernel data abort, pc=0xfffffff00d308824, far=0x8, x1=3, x2=2, x22=3, x26=0x1a0a0`；panicked task = **ave2_probe_create** 实锤。
- **换算**（slide 0x4824000 + base 0xfffffff007004000，公式 runtime−0xB828000；pc 心算错一次后用脚本批换 28 帧）：
```
崩溃链（foff）：sel5 executor 0x1b9d264 → Configure 公共 0x1a7b510 → 门链 0x1a771bc
  → 池校验 0x1b802ec → slot 表操作 0x1b6a280/0x1b6a644（0x1b66980 插入函数内部！）

```
- **崩溃机制**：trampoline 0x1ae080c（微型）：`mov w1,#3; mov w2,#2; bl 0x1a92d4c(3,2); ldr w0,[x0,#8]` —— **查询返回 NULL 后无检查直接 [NULL+8]**。x1=3/x2=2 是硬编码参数（非 opentype；x22=3 待溯）。
- **0x1a92d4c = 引擎 slot best-fit 分配器**：条目 0x70B（+8 type 过滤 >7、+0xc 容量≥1、+0x10 flags bit1、+0x18 高水位、+0x24 条件、+0x48 状态/水位**写回**）、循环体 0x1a92c34、count=[池+0x2d8]、步进 0x70。**返回 NULL = 无匹配 slot**。
- **与 w54 门统一**：slot 表 = [D+0x1c] 计数门的同一资源池的两个视图（type1 查到 1 个 <2 挂门；type3 查到 0 个 → NULL → 崩）。
- **二次复现（VT+type3）**：VT 硬编码活跃 + AVE2_OPENTYPE=3 → **再次 panic**（输出未回即崩）⇒ **type-3 slot 与系统负载无关，A13 硬件能力层不存在**。
- **利用判定**：NULL+8 是 DoS 级（NULL 页映射被 PPL/PAC 挡死）。**升级路径 = slot 表注入**：若 create/sel4 能往池 slot 数组写伪条目（type=3, cap≥1, flags 合法），查询命中 → `ldr w0,[伪slot+8]` = **从我们数据读 u32**（若值流向 out = 内核信息泄露原语；若继续作指针/size → 更强）。**下一班唯一主线：静态追 slot 数组（[池+0x2d8] 计数、条目基址）的写入者**——0x1b6a280 所在插入函数是已知一环，追它写入条目内容的来源（是否 copy 自会话/configure 载荷）。
- 资产：panic ips 已存 Documents；换算脚本；崩溃链全帧表。
