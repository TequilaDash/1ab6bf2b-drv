## key 语义最终修正（本轮核心突破）
1. **0x3183b24 是全 kernelcache 43 处调用的通用 API**（0x19ea958/0x1edbb28/0x1f10810/0x21a6ab8/0x24649cc/0x30016a0 等，跨多 kext），非 IOSurfaceRoot 私有。
2. **通用调用范式**：`0x3183b24(owner, sid, cookie)`，cookie = 各子系统自己的无参 getter() 返回值。旁证：另一 kext 调用点 0x19ea958 的 cookie = `0x800ae00()`（vm 口径）= **`mrs x0, tpidr_el1` 派生**（per-cpu/全局单例指针）。
3. AVE2 cookie getter `0x1a48d8c` = `adrp+add; ret` 返回 **0xfffffff00aa9f8d0**（AVE2 全局 client registry 单例地址，__DATA foff 0x3A9B8D0）。**6 个调用者**：0x1b9ab38（**dispatch wrapper**：每 selector 入口读 [cookie+0x20] 做存在性校验，selector 范围检查 w22-1<=9）、0x1ba28b0/0x1ba2c2c/0x1ba2d44（sel12/13 PowerOn/Off 深链区）、0x1ba98f8/0x1bab56c。
4. **注销路径实锤**：0x1b7f200（entry 0x1b7b200）遍历 base+0x170 数组（stride 0x10，4 项），[item+0x170]==cookie 则清除并 count-1；调用者 0x1b7ecd4（sel2/destroy 路径，`ldr x1,[x20]` 传 cookie）。断言串全文 "IOSurface in slot %08x has a mismatched surface ID of %08x"（**SID 32 位 slot ID**）。
5. **⇒ 完整模型**：cookie 是 AVE2 buffer 集合的 tag。注册 = buffer 分配时 cookie 写进条目+0x170（动态写入，静态搜立即数无效）；注销 = sel2/destroy 按 cookie 清除。**sel5 查表失败 = key=cookie 的 buffer 集合条目不存在 = 注册从未发生**。

- 本轮发现此前的"InitUCInfoPool 成功路径 tail jump 0x1b7f7e0"是误读（把 foff 0x1b762c8 的函数内容当成了 0x1a762c8）。

### InitUCInfoPool 真实流程（本轮定案）
```
0x1a7224c bl 0x1b671c0（查表：owner=[[pool+0x40]+0x18], key=cookie, SID）
  成功(w0=0) → 0x1a722c8: [session+0x588] 已被填 → hash → kalloc(0x7bd3330) → 0x1a767d4
             → 成功 0x1a72410 → 全局[0x7bc9638]单例 + [session+0x588] → **0x1a72450 bl 0x1b66980（创建+注册 buffer 集合）**
  失败(w0=-1015) → 0x1a72254 日志 → **x22=0 → 函数返回"成功"（失败被吞！）→ session+0x588 未填**
```
- **注册死锁实锤**：0x1b66980（创建+注册，内部 0x1b4f8fc→0x1b4ed70→0x3183ec4 事件对 + 0x1b538fc）只在查表成功后执行；首次查表必败 → 注册永不执行。

### 主线切换依据（参考/Ping-2o/REPORT_AVE_84607.md 精读）
- CVE-2026-84607 的修复 = iOS 27.0 beta b2→b4 的 kernel-memory hardening sweep：**~22 个 AVE_CalcBufSizeOf* 计算器全部加溢出守卫**（`size >= 0 && size <= 2147483647` 等）+ eEncType 状态守卫。
- **26.0.1（904.76.7）早于全部这些守卫**——整族计算器裸奔。
- **关键**：`AVE_CalcBufSizeOfMBInputCtrl` 尺寸的 memcpy 发生在 **sel4 Prepare 深链**（报告引 FINDINGS v132：PrepareMBInputCtrl memcpy；内核侧 saMBInputCtrl[i] 校验）——**sel4 已全通（KERN_SUCCESS 稳定复现），不需要 sel5**！
- LRB 只是 22 个计算器之一；MBInputCtrl/CodedData/MBStats/DPB 等每一个都是独立溢出面，且都在 sel4 可达范围。

### 26.0.1 定位成果（本轮静态）
- 字符串出土：`0x257221 'pBufSet->saMBInputCtrl[i].iAddr != 0'`（**BufSet = sel5 查的集合本体**）、`0x257d26 'pInfo->sInput.sMBInputCtrl.iAddr != 0'`、`0x2875e6 'MBInputCtrl'`、多处 `EnableMBInputCtrl %d`。
- 断言 xref → **BufSet 处理函数 = 0x1a55690**（大函数，tag 0x77 日志，行号 0x339/0x347/0x357 的断言群= saMBInputCtrl[i].iAddr 校验链）。
- DPBBuffer 日志群 @0x24e7a4+（DPB 计算器的运行时痕迹：w/h/level/num_ref_frame 全打印——**溢出配方调好时内核日志会直接报尺寸**）。

### 下一班精确行动（新主线，按序）
1. **找 sel4 Prepare 深链里 saMBInputCtrl 的分配/memcpy 点**：从 0x1a55690 或 Client_Prepare 0x1a7ae58 深链追 `sMBInputCtrl.iAddr` 的消费点，定位尺寸计算器函数（AVE_CalcBufSizeOfMBInputCtrl 26.0.1 等价物）。
2. **EnableMBInputCtrl 开关**：configure 输入里 EnableMBInputCtrl 字段偏移（0x268c62 fmt xref 换算后找），v33 的 MS patch 里没有它——开启后 sel4 深链才走 MBInputCtrl 分配。
3. **逆向计算器公式**（w/h/mode → 32 位 size），暴力搜溢出配方（w,h ∈ capability gate 内，iTotal > 0x7fffffff 或低 32 位回绕）。
4. 溢出命中后：sel4 的 memcpy undersized → 堆溢出 → panic/取证 → KRW。
5. frida-server 17.24.3 下载换源（备选 ghproxy.cc / mirror.ghproxy.com / 本地代理），恢复动态观测。
